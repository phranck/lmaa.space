# GitHub Sponsors money is not project money

The support page links `github.com/sponsors/phranck` as a way to help, and that listing carries seven plain price tiers and describes its owner as a macOS and iOS developer of twenty years. Nobody sponsoring there says which of the operator's projects they mean. The operator has decided that this money is theirs across everything they do rather than this site's, so it is not read and not counted.

## Consequences

Neither of the two possible read points is used, and using both would have been the trap: GitHub's own API reports a sponsorship when it happens, whilst the Stripe payout of the same money reaches the bank account weeks later, netted and lumped together with others. Counting both would count one donation twice.

The payout at the bank is already excluded by the positive list, because it carries none of this site's markers. Nothing has to be built to keep it out.

What would change the decision is a sponsors listing that belongs to the project rather than to the person, which on GitHub means an organisation with its own listing. Then a sponsorship is attributable by construction and the API reads it cleanly. That is a decision about how donations are collected, not about how they are read.
